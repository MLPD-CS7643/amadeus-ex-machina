# Requirements Document

## Introduction

This document specifies requirements for a deployable web application that enables users to upload audio files and receive chord annotations generated by a trained deep learning model. The system leverages existing PyTorch-based chord recognition models (CRNNModel) and provides a user-friendly interface for non-technical users to access chord transcription capabilities.

## Glossary

- **Web_Application**: The browser-based interface and backend server that handles user interactions and model inference
- **Audio_File**: Input music files in WAV, MP3, or FLAC format
- **Chord_Annotation**: Time-stamped chord labels in .lab format (start_time, end_time, chord_label)
- **CRNNModel**: The trained CNN+LSTM hybrid model stored at models/checkpoints/CRNNModel_best_model.pth
- **Chromagram**: 12-dimensional pitch class representation extracted from audio using librosa
- **Inference_Pipeline**: The processing chain that converts audio to chromagram, scales features, and runs model prediction
- **Scaler**: Pre-fitted StandardScaler stored at data/processed/scaler.pkl
- **Label_Encoder**: Pre-fitted LabelEncoder stored at data/processed/label_encoder.pkl
- **Upload_Zone**: The drag-and-drop interface component for file selection
- **Processing_Status**: Visual feedback indicating the current state of audio processing

## Requirements

### Requirement 1: Audio File Upload

**User Story:** As a musician, I want to upload audio files through a web interface, so that I can get chord annotations without installing software.

#### Acceptance Criteria

1. THE Web_Application SHALL provide an Upload_Zone that accepts drag-and-drop file input
2. THE Web_Application SHALL provide a file selection button as an alternative to drag-and-drop
3. THE Web_Application SHALL accept Audio_Files in WAV, MP3, and FLAC formats
4. WHEN an unsupported file format is uploaded, THE Web_Application SHALL display an error message indicating supported formats
5. THE Web_Application SHALL display the uploaded filename and file size after successful upload
6. THE Web_Application SHALL limit uploaded Audio_File size to 50MB maximum
7. WHEN a file exceeds the size limit, THE Web_Application SHALL display an error message with the size constraint

### Requirement 2: Audio Processing and Inference

**User Story:** As a user, I want the system to automatically process my uploaded audio, so that I receive chord annotations without manual intervention.

#### Acceptance Criteria

1. WHEN an Audio_File is uploaded, THE Inference_Pipeline SHALL extract Chromagram features using librosa
2. THE Inference_Pipeline SHALL apply the pre-fitted Scaler to normalize chromagram features
3. THE Inference_Pipeline SHALL load the CRNNModel from models/checkpoints/CRNNModel_best_model.pth
4. THE Inference_Pipeline SHALL load the Label_Encoder from data/processed/label_encoder.pkl
5. THE Inference_Pipeline SHALL generate Chord_Annotations by running model inference on scaled features
6. THE Inference_Pipeline SHALL decode predicted class indices to chord labels using the Label_Encoder
7. IF the model checkpoint file is missing, THEN THE Web_Application SHALL display an error message indicating system misconfiguration
8. IF the scaler or label encoder files are missing, THEN THE Web_Application SHALL display an error message indicating system misconfiguration

### Requirement 3: Processing Status Feedback

**User Story:** As a user, I want to see the processing status of my audio file, so that I know the system is working and when results will be ready.

#### Acceptance Criteria

1. WHEN audio processing begins, THE Web_Application SHALL display Processing_Status indicating "Processing audio"
2. WHILE audio is being processed, THE Web_Application SHALL display a progress indicator or loading animation
3. WHEN processing completes successfully, THE Web_Application SHALL update Processing_Status to "Complete"
4. IF processing fails, THEN THE Web_Application SHALL display Processing_Status as "Failed" with an error description
5. THE Web_Application SHALL display estimated processing time based on audio file duration

### Requirement 4: Chord Annotation Output

**User Story:** As a user, I want to download chord annotations in a standard format, so that I can use them with other music software.

#### Acceptance Criteria

1. WHEN inference completes, THE Web_Application SHALL generate a Chord_Annotation file in .lab format
2. THE Chord_Annotation file SHALL contain one line per chord segment with format: start_time end_time chord_label
3. THE Web_Application SHALL provide a download button for the Chord_Annotation file
4. THE downloaded file SHALL be named using the pattern: {original_filename}_chords.lab
5. THE Web_Application SHALL display a preview of the first 10 chord annotations before download
6. THE Web_Application SHALL format timestamps with 4 decimal places of precision

### Requirement 5: Chord Visualization

**User Story:** As a user, I want to see a visual representation of detected chords, so that I can quickly understand the chord progression without reading raw data.

#### Acceptance Criteria

1. WHEN inference completes, THE Web_Application SHALL display a timeline visualization of Chord_Annotations
2. THE visualization SHALL show chord labels positioned at their corresponding time segments
3. THE visualization SHALL use distinct colors or visual markers for different chord types
4. THE Web_Application SHALL display the total duration of the analyzed audio
5. THE visualization SHALL be scrollable for audio files longer than 60 seconds

### Requirement 6: Backend API

**User Story:** As a developer, I want a REST API for audio processing, so that the frontend can communicate with the inference backend.

#### Acceptance Criteria

1. THE Web_Application SHALL provide a POST endpoint at /api/upload for Audio_File uploads
2. THE Web_Application SHALL provide a GET endpoint at /api/status/{job_id} for checking Processing_Status
3. THE Web_Application SHALL provide a GET endpoint at /api/download/{job_id} for retrieving Chord_Annotations
4. WHEN a file is uploaded, THE Web_Application SHALL return a unique job_id for tracking
5. THE Web_Application SHALL return HTTP 400 status code for invalid file formats
6. THE Web_Application SHALL return HTTP 413 status code for files exceeding size limits
7. THE Web_Application SHALL return HTTP 500 status code for processing failures with error details

### Requirement 7: Deployment Configuration

**User Story:** As a system administrator, I want deployment instructions and configuration files, so that I can deploy the application to a production environment.

#### Acceptance Criteria

1. THE Web_Application SHALL include a requirements.txt or environment.yaml file listing all Python dependencies
2. THE Web_Application SHALL include a Dockerfile for containerized deployment
3. THE Web_Application SHALL provide environment variable configuration for model paths and file size limits
4. THE Web_Application SHALL include a README with deployment instructions for local and cloud environments
5. THE Web_Application SHALL configure CORS headers to allow cross-origin requests
6. THE Web_Application SHALL serve static frontend files from the backend server

### Requirement 8: Error Handling and Validation

**User Story:** As a user, I want clear error messages when something goes wrong, so that I understand what happened and how to fix it.

#### Acceptance Criteria

1. WHEN audio file loading fails, THE Web_Application SHALL display an error message indicating the file may be corrupted
2. WHEN chromagram extraction fails, THE Web_Application SHALL display an error message indicating unsupported audio format
3. WHEN model inference fails, THE Web_Application SHALL log the error details and display a generic error message to the user
4. THE Web_Application SHALL validate that uploaded files are not empty
5. WHEN an empty file is uploaded, THE Web_Application SHALL display an error message indicating the file is invalid
6. THE Web_Application SHALL handle network timeouts gracefully with retry suggestions

### Requirement 9: Performance Requirements

**User Story:** As a user, I want fast processing times, so that I can get results quickly and use the application efficiently.

#### Acceptance Criteria

1. THE Inference_Pipeline SHALL process a 3-minute audio file in under 30 seconds on CPU
2. WHERE GPU is available, THE Inference_Pipeline SHALL utilize GPU acceleration for model inference
3. THE Web_Application SHALL support concurrent processing of up to 5 audio files simultaneously
4. THE Web_Application SHALL implement request queuing when concurrent limit is exceeded
5. THE Web_Application SHALL clean up temporary files after processing completes or after 1 hour timeout

### Requirement 10: Security Requirements

**User Story:** As a system administrator, I want security measures in place, so that the application is protected from malicious use.

#### Acceptance Criteria

1. THE Web_Application SHALL validate file extensions match actual file content (magic number verification)
2. THE Web_Application SHALL sanitize uploaded filenames to prevent path traversal attacks
3. THE Web_Application SHALL implement rate limiting of 10 requests per minute per IP address
4. THE Web_Application SHALL store uploaded files in a temporary directory with restricted permissions
5. THE Web_Application SHALL delete uploaded Audio_Files after processing completes
6. THE Web_Application SHALL not expose internal file paths or system information in error messages
